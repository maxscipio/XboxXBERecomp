# SDK patches

Gun Valkyrie (XDK 4134, title 49470017). Merged from `..\valkyrie\XboxXBERecomp` (branch `valkyrie`, on top of `ref`).

| Area | Files | Why | Origin |
|------|-------|-----|--------|
| XDK 4134 data | `xdk/4134/layout.toml`, `xdk/4134/signatures.toml` | New XDK build. Layout verified against the Valkyrie code; signatures are a proxy derived from Burnout (4361) because no 4134 libs exist | valkyrie |
| Pad recognition | `runtime/core/input.cpp` | `SDL_HINT_JOYSTICK_DIRECTINPUT` is "0": with "1" an Xbox One pad shows up as a raw DirectInput joystick SDL has no mapping for. Burnout's `kPadMapping` is no longer used by default; a game that needs DirectInput pads must set the hint back | valkyrie |
| XInputPoll HLE | `runtime/xdk/xapi.cpp` | The guest `XInputPoll` reads the handle as an XPP device object and fails on the HLE handle, so the title closed and reopened the pad every ~100 ms and never called `XInputGetState`. Map it with `XInputPoll = <addr>` in `game.toml` (`SYM_XInputPoll`); `XInputClose` needs mapping the same way | valkyrie |
| Depth buffer size | `runtime/gpu/{d3d12,vulkan}.cpp` | `BindTargets` dropped a depth buffer whose size differed from the colour target's. A depth buffer larger than the target is valid (it covers the top left corner), so only a smaller one is dropped. Fixed distant terrain vanishing while thrusting (a 512x384 distortion pass under a 640x480 depth buffer) | valkyrie |
| Upstream PR #29 (cherry-picked, not merged) | `runtime/gpu/{backend.h,d3d12.cpp,render_thread.cpp,shaders.cpp,vulkan.cpp}`, `runtime/xdk/{d3d8.cpp,xnet.cpp}`, `harness/null_backend.cpp` | `CopyRects` from the back buffer honors multisampling and `SetBackBufferScale` (`Backend::Copy` gets `src_kx`, `src_ky`; Vulkan accepts them but copies unscaled); wrap is kept on stages with a texture matrix or texgen; fixed function takes `w - z` from one matrix column against z-fighting with a distant far plane; `accept()` inherits the listener's blocking mode. `SetBackBufferScale` placeholder is `FFFFFE0C`, `DrawIndexedVerticesUP` keeps `FFFFFE0B`. Not taken: the DirectSound stream additions, the SDL assertions switch, and the recompiler's `Walk` overlap change (regenerates every game), plus the `DrawIndexedVerticesUP` and `NtUserIoApcDispatcher` copies we already have | Joshhhuaaa via PR #29 |
| Initial pad enumeration | `runtime/xdk/xapi.cpp` | `XInitDevices` filled the XPP record at once, so the title's first `XGetDeviceChanges` saw a pending insertion and its input init failed (E_FAIL), sending it to the dash with a black screen. The record is now filled by `XGetDevices` or the 250 ms poller, as with the bus enumerating asynchronously. Also map `XapiVerifyMediaInDrive` (the disc check) in `game.toml` | valkyrie |
| Renderer 3D widening (`app::g_widen_3d`) | `runtime/app/app.h`, `runtime/gpu/shaders.cpp`, `runtime/gpu/d3d12.cpp` | For titles that draw 3D for 4:3 and have no widescreen mode. Non-pretransformed draws into a guest-screen-sized target get the clip-space X narrowed by `(4/3)/Aspect()` (`hud.z`), so the wider output shows more world instead of stretching it. D3D12 only; the title sets the flag in `OnInit`. The game's CPU frustum culling stays 4:3. With the flag, `HudSqueeze` keeps the 2D in a centred 4:3 part at 16:9 (16:9 part when wider) | valkyrie |
